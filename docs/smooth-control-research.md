# Endfield 视觉控制平滑方案调研

日期：2026-09-09
范围：YOLO 检测点 → 控制算法 → 整数鼠标计数 → KMBox；本文件只做研究与实施建议，不改生产代码。

实施状态（2026-09-09）：已完成轻量目标锁定滞回、带时间戳的 One Euro 瞄准点过滤，以及现有动态 P/EMA 的帧率归一化。本轮按要求没有引入二阶 `smooth_time` 跟随器，也没有增加速度、加速度或 jerk 轨迹控制。

## 结论先行

建议的主路线不是继续堆高当前的 `smoothing`，而是把三个性质不同的问题分开处理：

1. **目标身份稳定**：保留当前锁定目标，用门控和切换滞回避免相邻框之间逐帧跳选。
2. **测量去噪**：对锁定目标的二维瞄准点使用带真实时间戳的 **One Euro Filter**；慢速时强力抑制 YOLO 框抖动，快速位移时自动放宽带宽以减少拖尾。
3. **运动成形**：用**临界阻尼式二阶跟随器**产生连续速度，再加二维向量速度/加速度上限。用户只看到一个“平滑度”旋钮，它控制 `smooth_time`（或等价自然频率）；平滑度越低，响应越快、力度越大，平滑度越高则反之。
4. **整数输出**：保留现有小数余量累加，但从固定频率控制节拍均匀发出计数，并按二维向量限幅，避免逐检测帧一次的大块移动和斜向超额。

推荐链路：

```text
YOLO detections
  -> target lock + switch hysteresis
  -> timestamped One Euro filter on aim point (x, y)
  -> critically damped 2-D response (one user knob: smooth_time)
  -> radial speed/acceleration clamp
  -> fractional residual / integer count scheduler
  -> KMBox
```

不要同时保留当前的输出 EMA；多个低通环节叠加只会增加延迟。One Euro 应是唯一的测量低通，二阶跟随器负责运动形状。

## 改动前基线为什么会抖

当前路径在 `rhodes_fast/kmbox_control.py` 中是：原始框中心误差 → 距离相关 P 增益 → 固定每帧 EMA → 每轴死区/限幅 → 四舍五入后发送。`pipeline.py` 每处理完一个检测帧才调用一次 `move_toward()`。

由代码可直接看到以下风险：

- `alpha = smoothing` 是**每帧常数**，没有使用相邻样本的真实 `dt`。因此相同设置在不同帧率下不是相同的物理时间响应。
- 平滑的是 `error * kp` 后的**输出指令**，不是噪声源本身（YOLO 框中心）。距离相关的非线性增益会先把检测噪声调制进指令。
- 任一轴发生符号反转时，平滑状态和余量被硬清零。这能防止旧方向拖尾，却制造速度不连续，且 X/Y 独立处理。
- `select_target()` 每帧直接选离中心最近的框，没有目标 ID、关联门控或切换滞回；两个候选接近时可能在它们之间跳选，任何滤波器都很难掩盖这种大跳变。
- `max_step` 是逐轴上限，所以斜向最大向量长度可到单轴上限的 `sqrt(2)`；它限制位移，但不限制相邻指令之间的速度/加速度变化。
- 小数余量累加已经解决了“低增益永远舍入为零”，应保留；但低于 1 count/tick 的命令天然会形成 0/1 脉冲，若发送节拍跟随不稳定的检测帧，这些脉冲仍会感觉不均匀。

本轮已确认的基线现象与上述分析吻合：

- 静止目标叠加 `±3 px` 块状检测噪声，会变成 `±1` 的交替微修正；96 帧内出现 7 次方向翻转。
- 相同固定每帧平滑设置在经过 `0.25 s` 后，30/60/120 FPS 的剩余误差分别为 `43/20/5 px`。也就是说，手感明显取决于帧率，而不是只取决于旋钮值。

从一阶 EMA 看，当前 `alpha=0.35` 的记忆衰减时间约为 2.32 帧；换成墙钟时间约为 77 ms（30 FPS）、39 ms（60 FPS）、19 ms（120 FPS），这正是帧率依赖的根因。

## 候选算法比较

| 路线 | 抗静止抖动 | 快速跟随/延迟 | 变帧率 | 参数与风险 | 对本项目的判断 |
|---|---:|---:|---:|---|---|
| 时间常数 EMA | 好 | 固定折中，越稳越慢 | 使用 `dt` 后好 | 1 个时间常数，最简单 | 很适合作为低风险基线，但无法同时做到静止稳、快速时低延迟 |
| One Euro Filter | 很好 | 速度越高截止频率越高，拖尾较小 | 原算法使用时间戳 | 内部 2 个主要参数；可固定 `beta`，只暴露一个旋钮 | **最适合 YOLO 瞄准点的测量去噪** |
| 临界阻尼二阶/弹簧 | 中等；目标本身有噪声时仍会被驱动 | 响应自然，可做到无意图过冲 | 显式使用 `dt` 后好 | 固定阻尼比 1 后只需响应时间 | **最适合单“平滑度/力度”旋钮和运动成形** |
| 速度/加速度/jerk 限制 | 不消除低频测量噪声 | 保证动作连续，但上限过低会追不上 | 必须按秒和 `dt` 定义 | 需要隐藏的安全上限；jerk 规划更复杂 | 很适合作为二阶跟随器后的安全层；完整 Ruckig 对本项目偏重 |
| P / PD / PID | P 简单；D 会放大未滤波检测差分 | 调好可快，但依赖模型与固定周期 | 周期不稳时容易变味 | 多增益、D 滤波、积分防饱和 | 保留 P 概念可以；**不建议直接上完整 PID** |
| Alpha-Beta / Kalman | 好，可估计速度并跨短暂漏检预测 | 预测降低表观延迟；模型错时会过冲 | 状态转移矩阵可纳入 `dt` | 过程/测量噪声难调，身份关联仍需另做 | 第二阶段候选；当漏检/预测是主矛盾时再上 |
| SORT / ByteTrack 类追踪 | 解决换目标和短漏检，不直接让轨迹丝滑 | 关联正确时显著稳定 | 可处理逐帧检测，需注意低帧率 | 增加 track 状态和匹配逻辑 | 完整多目标追踪可后置；先做轻量锁定与滞回即可 |

### 1. 时间常数 EMA：应有的最低基线

一阶低通可写为：

```text
y <- y + alpha * (x - y)
alpha = 1 - exp(-dt / tau)               # 精确匹配连续一阶响应
```

One Euro 原论文也给出了随采样周期变化的 RC 离散形式 `alpha = dt / (dt + tau)`，而不是固定每帧 alpha。论文明确说明：alpha 越小，抖动越小但延迟越大，并专门用实际采样间隔处理事件驱动系统的频率波动（[Casiez, Roussel & Vogel, CHI 2012, pp. 2528–2529](https://gery.casiez.net/publications/CHI2012-casiez.pdf)）。

用户旋钮应显示易懂的“平滑度”，内部映射到毫秒时间常数/半衰期，而不是裸 `alpha`。对数映射比线性映射更容易覆盖 20–200 ms 而仍能细调。Raw Accel 的官方指南也使用 EMA 半衰期描述平滑，并区分“输出平滑”（会直接增加输入到输出的延迟）和只用于估计速度/增益的平滑（[Raw Accel official guide](https://github.com/RawAccelOfficial/rawaccel/blob/master/doc/Guide.md)）。

优点是改动小、容易验证。缺点是固定截止频率无法同时满足静止稳定和快速转向低延迟，论文的鼠标实验也观察到单指数平滑为了匹配静止抖动而需要很低 alpha，随之产生明显滞后。

### 2. One Euro Filter：最适合测量端

One Euro 是速度自适应的一阶低通：

```text
cutoff = min_cutoff + beta * abs(filtered_derivative)
```

慢速时采用低截止频率压住抖动；速度高时提高截止频率降低延迟。原论文就是针对交互式光标/跟踪输入中的 jitter-lag 矛盾，并且算法从时间戳计算采样周期，适合本项目的 UDP/推理帧率波动。论文报告的示例比较中，在匹配静止抖动的条件下，One Euro 比移动平均、单/双指数和平调过的 Kalman 具有更小的运动延迟（[原论文与算法](https://gery.casiez.net/publications/CHI2012-casiez.pdf)，[作者维护的实现与调参页](https://gery.casiez.net/1euro/)）。

注意：它原生有 `min_cutoff` 和 `beta` 两个主要参数，并非天然一个旋钮。实现时可以离线用真实轨迹确定 `beta` 和导数截止频率，只把 `min_cutoff` 或统一的“平滑度”映射暴露给用户；高级参数保留在配置文件中。X/Y 应共用基于二维速度模长的自适应 cutoff，避免轴向速度不同造成路径形状扭曲。

### 3. 临界阻尼二阶跟随器：最适合单旋钮

标准二维临界阻尼响应可以对每轴维护位置/速度状态：

```text
acceleration = omega^2 * position_error - 2 * omega * velocity
```

固定阻尼比为 1 后，唯一决定“快/猛”与“慢/柔”的核心量就是自然频率 `omega`，或其倒数形式 `smooth_time`。降低 `smooth_time` 会同时提高初始加速度和到达速度，正好符合“一个平滑旋钮控制力度”的直觉。

Unity 的官方 `SmoothDamp` 是成熟的一旋钮参考：API 只需 `smoothTime`、当前速度和 `deltaTime`，文档说明较小的 `smoothTime` 更快，算法为 spring-damper 式并尝试避免越过目标；官方源码用 `omega = 2 / smoothTime`、显式 `deltaTime`、最大速度钳制和越界保护（[Unity API](https://docs.unity3d.com/ja/current/ScriptReference/Mathf.SmoothDamp.html)，[Unity C# reference source](https://github.com/Unity-Technologies/UnityCsReference/blob/master/Runtime/Export/Math/Mathf.cs#L308-L337)）。这里应重新实现等价数学，不复制受参考源码许可限制的代码。

二阶跟随器不是测量去噪器：如果直接喂入每帧跳动的 YOLO 点，它仍会持续受激。因此推荐在轻量 One Euro 之后使用，而不是替代 One Euro。现有的“符号反转即清零”则应由连续阻尼刹车取代。

### 4. 速度、加速度和 jerk 限制

单纯 `max_step` 只限制一帧能走多远，不能阻止下一帧从 `+8` 突然跳到 `-8`。更自然的限制是在物理时间单位下约束二维速度变化：

```text
delta_v = desired_v - current_v
delta_v <- radial_clamp(delta_v, max_acceleration * dt)
current_v += delta_v
```

FIRST/WPILib 的官方文档指出，slew-rate limiter 直接限制变化率，适合柔化速度设定；若控制的是位置，应使用带最大速度和最大加速度的梯形运动轮廓（[Slew Rate Limiter](https://docs.wpilib.org/en/latest/docs/software/advanced-controls/filters/slew-rate-limiter.html)，[Trapezoidal Motion Profiles](https://docs.wpilib.org/en/latest/docs/software/advanced-controls/controllers/trapezoidal-profiles.html)）。

若未来要求更严格的“加速度本身也不能突变”，Ruckig 能在线生成同时满足速度、加速度、jerk 限制的时间最优轨迹（[Berscheid & Kröger, RSS 2021](https://www.roboticsproceedings.org/rss17/p015.pdf)，[官方实现](https://github.com/pantor/ruckig)）。但 YOLO 目标每帧都可能移动或改向，完整 jerk-limited 重规划的复杂度和调参成本目前不划算；先用临界阻尼加径向加速度上限。

### 5. PD/PID：不是当前首选

当前动态 Kp 本质上已经是非线性 P 控制。增加 D 可以提供刹车，但对原始 YOLO 误差做差分会放大高频框噪声；工程 PID 通常给 D 项加一阶滤波。MathWorks 的官方 PID 定义明确包含导数滤波时间常数 `Tf`（[PID controller reference](https://www.mathworks.com/help/control/ref/pid.html)）。

完整 PID 还需要固定/已知控制周期；WPILib 官方实现明确警告，调用间隔与配置周期不一致会产生非预期行为（[WPILib PIDController](https://docs.wpilib.org/en/stable/docs/software/advanced-controls/controllers/pidcontroller.html)）。本项目当前检测驱动调用不满足这个前提。I 项对屏幕误差通常没有必要，并会在限幅、漏检或目标切换时积累 windup。因此最多考虑“滤波后的 PD”，但临界阻尼二阶形式更容易压缩成一个用户旋钮。

### 6. Alpha-Beta / Kalman 与目标追踪

Kalman 滤波适合将位置与速度放入状态，在噪声下估计目标并对短漏检做预测；其理论来自状态转移、过程模型和测量模型（[Kalman 1960 原论文 DOI](https://doi.org/10.1115/1.3662552)）。Alpha-Beta 是常速度 Kalman 的固定增益近似，经典论文给出了兼顾噪声抑制与机动跟随的固定参数跟踪方程（[Benedict & Bordner 1962 DOI](https://doi.org/10.1109/TAC.1962.1105477)）。

代价是必须可靠估计检测噪声、目标机动噪声和 `dt`，模型失配会产生过冲或错误预测。One Euro 原论文也指出，在不知道过程/测量协方差时 Kalman 调参困难。对于 320×320、单个瞄准点，先用 One Euro 通常更稳妥。

追踪和滤波不是同一问题。SORT 原论文用 Kalman 加逐帧关联实现 260 Hz 的在线跟踪，说明简单状态与关联可以很轻（[Bewley et al., SORT](https://arxiv.org/abs/1602.00763)）。ByteTrack 通过把低置信度检测也与已有轨迹关联来减少遮挡造成的轨迹碎裂（[ByteTrack 原论文](https://arxiv.org/abs/2110.06864)，[作者官方代码](https://github.com/FoundationVision/ByteTrack)）。本项目未必需要完整 MOT；先做“当前框优先”的轻量状态机：

- 当前目标仍在位置/IoU 门内时继续锁定。
- 新候选必须明显更优（例如距离改善 15–25%）并连续 2–3 帧才切换。
- 短暂漏检保持预测 1–3 帧，但停止继续加速；超时后清空全部滤波/速度/余量状态。
- 真正换目标时立即重置测量滤波器到新测量，并将输出速度平滑制动，而不是沿用旧目标历史。

这些阈值是待回放标定的工程初值，不是论文结论。

## 单“平滑度”旋钮的具体设计

建议 UI 只显示 `平滑度 0–100`，数值越高越平滑、力度越柔和。内部采用对数映射得到 `smooth_time`，例如先扫 `20–180 ms`：

```text
t = smoothness / 100
smooth_time = 0.020 * (0.180 / 0.020)^t
omega = 2 / smooth_time
```

对数映射能让低延迟区仍有足够分辨率。`smooth_time` 同时控制二阶响应的速度与力度；One Euro 的 `beta`、导数 cutoff、最大速度和最大加速度作为经过标定的隐藏安全参数。若产品确实需要让平滑旋钮同时改变静止稳定度，可让它只小范围联动 `min_cutoff`，但不要让一个旋钮无约束地同时改五六个参数，否则不同设置难以解释和回归。

建议保留一个隐藏的“高级”区而非删除参数：

- 普通用户：只有平滑度。
- 高级/诊断：`min_cutoff`、`beta`、最大速度、最大加速度、锁定滞回。
- 原有三项动态 P 参数先保留在配置兼容层，默认不在主 UI 暴露；完成 A/B 测试后决定是否移除。

## 整数鼠标计数与发送节拍

现有 remainder 累加方向是正确的：它保证长期平均移动不会因每帧取整而消失，思想上类似在整数网格上累计误差的数字绘图方法（[Bresenham, IBM Systems Journal 1965, DOI](https://doi.org/10.1147/sj.41.0025)）。但还需处理时间分布：

- 检测线程只更新“最新目标状态”；控制线程以稳定节拍读取它并发出较小步长。建议先测 KMBox/网络可承受频率，再在 100–250 Hz 区间 A/B，不应凭空固定为高频。
- 所有速度、加速度与滤波参数用 `counts/s`、`counts/s²` 和秒定义；检测时间戳用于 One Euro，发送时间戳用于轨迹积分。
- 对 `(x,y)` 做**向量模长限幅**，不要分别 clamp 两轴。
- 余量应在“成功发送”后提交；发送失败、释放触发键、锁丢失超时和真正换目标时要有明确 reset 语义。
- 若 KMBox 只能在检测频率下可靠发送，就不要另起高频线程；改为用时间归一化算法并在回放里验证低频脉冲。设备能力需要单独基准测试。

## 推荐实施顺序

### 阶段 A：先消除确定性缺陷

1. 为每个检测和控制更新传入单调时钟时间戳。
2. 增加轻量目标锁定、位置/IoU 门控和切换滞回。
3. 把固定每帧 EMA 替换为作用在瞄准点上的 `dt` 感知 EMA，先建立最小基线。
4. 移除逐轴符号反转硬清零，改为连续制动；改用二维向量限幅。

### 阶段 B：A/B 两个候选

- A：时间常数 EMA + 临界阻尼运动成形。
- B：One Euro + 临界阻尼运动成形（推荐预期赢家）。

两组共用相同锁定逻辑、整数调度器和安全上限，以免把其他差异误认为滤波效果。

### 阶段 C：只在数据证明需要时增加复杂度

- 若主要失败是短漏检/匀速目标拖尾：增加 Alpha-Beta 或常速度 Kalman 预测。
- 若主要失败是多人交叉时换错目标：升级为 SORT/ByteTrack 类关联。
- 若主要失败是加速度变化仍可见：再考虑 jerk 限制；不直接上完整 Ruckig。

## 测试方法与验收指标

先记录真实运行轨迹，只记录数据而不改变控制：单调时间戳、全部检测框/置信度、选中目标、滤波点、浮点期望输出、整数实际输出和发送成功/失败。用同一份轨迹离线回放所有算法，避免靠主观感受反复调参。

至少包含以下场景：

1. 静止目标：真实检测噪声，以及已确认的 `±3 px` 块状噪声。
2. 阶跃：目标从中心突然移到 20/60/120 px。
3. 匀速与加速移动：水平、垂直和 45° 斜向。
4. 快速反向：检查过冲、硬停和余量符号。
5. 变帧率：相同轨迹按 30/60/120 FPS，并加入帧间隔抖动和 1–3 帧丢失。
6. 双目标靠近/交叉：检查目标切换次数。
7. 整数低速：期望每 tick 小于 1 count，检查脉冲间隔和累计误差。

核心指标：

- 静止时：输出 RMS、P95 峰峰值、方向翻转次数、每秒非零微修正次数。
- 响应时：50%/90% 到达时间、2% settling time、最大过冲。
- 平顺度：速度变化 RMS、加速度/jerk P95；同时看二维路径曲率，不能只看 X/Y。
- 帧率一致性：30/60/120 FPS 在相同墙钟时刻的误差差异。
- 量化：期望浮点累计量与实际整数累计量之差、0/1 脉冲间隔方差。
- 追踪：身份切换数、漏检保持后恢复时间、错误锁定持续时间。
- 延迟：检测到首个有效 KMBox 指令的时间，以及端到端 P50/P95。

建议第一轮门槛使用相对基线而非拍脑袋绝对值：静止方向翻转和输出 RMS 至少下降 50%，帧率变化后的同一墙钟误差差距至少下降 80%，且 90% 到达时间恶化不超过 15%、无新增可见过冲。达到后再由实机盲测在 3–5 个平滑档位中确认手感。

## 最终判断

最可能快速见效的是 **目标锁定滞回 + 带时间戳的 One Euro 测量滤波**；最符合用户记忆中“只调一个平滑旋钮就能控制力度”的，是在它后面使用固定阻尼比的**二阶 `smooth_time` 跟随器**。Kalman、完整 PID、完整 jerk-limited 轨迹规划都有合理用途，但当前都不是解决这次抖动的第一选择。
