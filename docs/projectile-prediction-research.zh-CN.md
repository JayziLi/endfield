# Endfield 有限弹速投射物预测研究

日期：2026-09-13。范围：类似守望先锋的游戏投射物、离线仿真与视觉预测。本文保留最初研究与方案依据；后续已实现算法库版 `kalman_projectile`，具体行为和使用方法见 [使用说明](kalman-projectile-guide.zh-CN.md)。未测得游戏实战命中率。

## 用户确认后的接入范围

用户确认输入由 OBS 采集屏幕中心 320×320 区域，采集目标频率 240 Hz；当前 FOV 105、不开镜。用户提供的“1600”保留原义，可能指鼠标 DPI，不能当作完整的游戏内灵敏度或像素/计数换算。灵敏度、预测手感由玩家自行调节；不要求选择英雄、填距离，也不接管开火时机。

配置检查确认 `settings.txt` 与 `config.toml` 均选择 `udp_jpeg`，接收尺寸 320×320。`UdpSource._publish()` 在输入尺寸不匹配时做缩放，没有中心裁剪；中心裁剪是用户确认的 OBS 上游设置。240 Hz 是用户提供的采集条件，并非本轮实测接收速率。预测应采用帧时间差；当前 JPEG 协议没有源采样时间戳，接收首包时刻只能作为近似时间基准，不能据此宣称已测出全部端到端延迟。

第一版按“玩家手调的屏幕空间预测”设计，弹速资料只用于解释参数量级，不作为硬编码英雄表。建议界面参数如下，范围属于待验证的设计值：

| 参数 | 建议交互 | 含义 |
| --- | --- | --- |
| 弹道提前时间 | 0–500 ms 滑块和数值输入，±5 ms 微调；高级输入可到 1000 ms | 在原有控制补偿之外的额外预测时间；0 关闭额外弹道提前 |
| 变向响应 | 慢—快滑块 | 调整运动估计对新观测的响应；快更易跟上反向，也可能增加抖动 |
| 最大提前距离 | 像素数，高级项 | 对预测偏移做二维长度限制，避免大提前量将瞄准点推到局部画面外 |
| 视角补偿比例 | 高级项，玩家标定 | 校准已发鼠标计数到局部画面位移的关系；不能只由 DPI 推出 |

预设按钮可为 0、50、100、200、300、500 ms，只代表时间档位，不绑定英雄，也不表示某档已经验证最佳。未启用时保持额外提前为 0；研究时可从 100 ms 开始逐步调节。避免再增加与时间完全等价的“提前强度”主滑块，以免玩家同时调两个相乘参数。

当前方案的明确边界：固定时间参数针对玩家常见交战距离调手感，不会自动适配所有距离；不包含重力弹道的完整求解。即使使用卡尔曼，远距离随机变向也不能保证准确。FOV 105 可作为玩家配置背景，纯像素预测无需把它设为必填输入。

## 结论

可以兼容。卡尔曼滤波用于估计带噪观测下的位置、速度及不确定度；弹道模型用于决定预测多远以及提前瞄准哪里。建议先比较现有速度前馈与二维匀速卡尔曼，在固定飞行时间下验证，再研究距离相关飞行时间和重力。不能根据历史位置确定玩家尚未表现出来的突然变向。

卡尔曼的预测、观测更新、过程噪声和测量噪声接口可参考 [OpenCV 官方文档](https://docs.opencv.org/4.13.0/dd/d6a/classcv_1_1KalmanFilter.html)；理论背景见 [Welch 与 Bishop 的卡尔曼滤波介绍](https://www.cs.unc.edu/~welch/media/pdf/kalman_intro.pdf)。下面的集成顺序是结合本仓库的工程判断。

## 当前代码具备什么

- `rhodes_fast/aim_algorithms/builtin.py` 的 `Feedforward`：从误差变化加上估计已生效的鼠标指令，估计目标位移，经 EMA 平滑后乘回路延迟帧数。速度单位实际是像素/调用帧，并没有按 `dt` 换成像素/秒。
- 同文件的 `InFlightFeedforward`：另外扣除已经发出、尚未在画面体现的鼠标指令。这里的 in-flight 是控制指令在途，不是弹丸在途。
- `loop_delay_frames` 同时控制速度估计的指令对齐、在途指令窗口和提前量。因此不能直接用它代替“回路延迟 + 弹丸飞行时间”。
- `rhodes_fast/aim_algorithms/contract.py` 的 `Observation` 提供误差、`dt`、帧序号、指令历史和比例增益；没有距离、弹速、相机姿态、采集时刻、检测置信度或框尺寸。`Detection` 本身有框和置信度，但当前算法接口没有传入。
- `rhodes_fast/kmbox_control.py` 中 `dt` 来自控制调用时的 `perf_counter()`，不等于源画面采样间隔。进入原始误差死区后，会在调用算法前清空状态并返回。这会阻止持续维护速度和判断未来预测点是否需要移动。
- `rhodes_fast/pipeline.py` 已在目标切换时调用 `forget_target()`，清理目标状态并保留已发出的指令；这一分离可以复用。
- `tools/sim_strafe.py` 已模拟左右变向、画面延迟和检测噪声，但 `hit_rate` 是当前准星误差落入阈值的比例，没有弹丸轨迹或碰撞。循环使用实际执行时钟调用控制器；评估依赖 `dt` 的新算法前，需要注入仿真时钟。

以上是对当前源代码的直接检查；旧产品文档对内置算法的描述已落后，本文以源码为准。

## 第一阶段：固定飞行时间的屏幕空间研究

建议链路：目标关联 → 相机运动补偿 → 位置/速度估计 → 未来位置预测 → 控制器输出。

使用 `[x, y, vx, vy]` 匀速状态，以秒为时间单位，依据真实采样间隔构造转移矩阵和过程噪声。区分两种时间：

1. **控制回路延迟**：用于将发出指令与画面中的相机运动对齐，估计尚未体现的控制量。
2. **观测到命中的时间**：从目标观测时刻到投射物生成的延迟 `L`，加弹丸飞行时间 `t`。`L` 包含哪些采集、处理、执行、前摇环节必须明确，不要重复累计，不要直接把网络 RTT 当作这个值。

在已经补偿视角运动、短时投影近似不变的坐标中：

```text
T = L + t
预测点 ≈ 观测位置 + 估计速度 × T
```

若状态已经外推到当前时刻，则只外推剩余时间，避免再次累计观测年龄。当前项目的“已生效鼠标计数加回像素误差”只是一种近似；需要标定计数到画面位移的关系，人工转视角、后坐力、自身平移也未必能从这些指令恢复。

例如纯假设横向速度 200 像素/秒、观测到生成延迟 40 毫秒、飞行时间 160 毫秒，总预测时间 0.2 秒，对应约 40 像素的提前量。这不是任何具体英雄的实测参数。

新增 `projectile_flight_ms`、`spawn_delay_ms` 等独立参数可做初步实验；保持原控制延迟含义不变。持续更新估计器，输出死区应结合最终预测误差判断；不要仅因当前框位于准星中心就重置运动状态。低置信度、短暂漏检和变向应降低提前量或增大不确定度；身份变化则重置目标估计。

## 第二阶段：距离相关的游戏拦截模型

若已知目标世界位置 `p`、速度 `v`，投射物生成时的发射位置 `s`，弹速 `c`，假设目标匀速、弹丸直线匀速、无重力且不继承发射者速度：

```text
r = p + v*L - s
|r + v*t| = c*t
(v·v - c²)*t² + 2*(r·v)*t + r·r = 0
预测命中点 = p + v*(L+t)
```

这是由两者在同一时刻相遇直接推导的运动学关系，不是滤波器的功能。取有效解中最小正根；处理近线性退化、负判别式、无正根和过长预测时间。距离/弹速只是初始近似，目标迎面或远离时应求解相遇时间。有重力、加速度或弹速变化时要换成对应游戏模型；也要分清目标命中位置和弹丸初始发射方向。

仅靠二维框无法直接代入这个世界坐标方程。透视投影 `u = fx*X/Z + cx` 表明像素速度受深度和相机影响，像素/秒不能和游戏单位/秒混用。投影依据见 [OpenCV 相机模型](https://docs.opencv.org/4.5.1/d9/d0c/group__calib3d.html)。由此推断：没有深度或标定时，固定时间二维预测只能作为局部近似；框高估距还受角色体型、姿态、遮挡和 FOV 影响。

## 卡尔曼与变向

匀速卡尔曼适合估计平滑速度和测量噪声，不保证优于调好的 EMA。增大过程噪声可以加快适应机动，但可能增加抖动；纯匀加速外推也可能在急停、反向时明显过冲。根据新观测残差调整预测强度，是优先于复杂模型的实验方向。

若简单模型的局限已被数据证实，再比较匀速、加速等多模型的 IMM。[MathWorks trackingIMM 文档](https://www.mathworks.com/help/fusion/ref/trackingimm.html)描述了其并行滤波和模型概率更新。它仍需要新观测才能识别变向，并不能消除未来输入的不确定性。

## 验证设计

先以相同数据、相同时间戳和相同预测时长比较：不预测、平滑差分速度、匀速卡尔曼。覆盖匀速、急停、随机反向、跳跃、漏检、框跳变、目标切换、视角运动和帧率变化。

测量未来位置误差的均值与 P95、反向后恢复时间、低置信度时的偏移；扩展仿真以保存发射时的方向并推进弹丸，记录碰撞命中率与最近擦过距离。不能用当前准星覆盖率代替投射物命中率，也不能用从未来真值得出的参数给预测器提供信息。

完成固定时间验证后，才加入距离、速度、重力和前摇的游戏参数，按不同距离和变向强度分别报告。本文未执行这些实验，因此不承诺具体命中率收益。
